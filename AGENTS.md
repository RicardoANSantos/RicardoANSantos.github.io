# Ricardo N. Santos's professional website

This repository is the durable context for maintaining Ricardo's academic website.
Read this file before editing. It is a set of project instructions, not a running agent.

## Purpose and design

- Present Ricardo's research, publications, CV, photos, and professional contact details.
- Preserve the simple academic layout: warm off-white background, forest-green links,
  serif headings, generous spacing, and responsive pages. Do not add dashboards,
  public chatbots, accounts, trackers, or other unrelated functionality.
- Keep research writing accurate, approachable, and concise. Preserve isotope symbols,
  accents, author order, and publication status.

## Source of truth

- User-provided new material supersedes older site content.
- `assets/Ricardo_CV.pdf` is the current downloadable CV (October 2026 at initial setup).
- `data/publications.json` is the bibliography. `publications.qmd` is generated by
  `scripts/render_publications.py`; edit the JSON, not the generated page.
- `data/projects.json` is the research-project source. `scripts/render_projects.py`
  generates `research.qmd` and `projects/*.qmd`; update the JSON for project text,
  groupings, dates, roles, photo paths, alt text, and captions. Confirm uncertain
  ongoing/past assignments with Ricardo when new information is supplied.
- Other `.qmd` files are the source for prose. `styles.css` and `theme.scss` control appearance.
- `dist/` is generated output; do not edit it directly.
- Do not infer a completed PhD from an anticipated defense date, or update an
  affiliation because time has passed. Use Ricardo's explicit update or a verified source.
- Do not invent paper acceptance, DOI, claims, coauthor identities, dates, locations,
  institutional logos, or photo captions. Keep submitted and in-preparation work
  separate from peer-reviewed publications.

## Update workflow

1. Inspect the supplied document, paper, image, or update. Ask only when missing
   information materially changes a factual claim or publication decision.
2. Update the relevant source files and all affected pages. Replace the downloadable
   CV only when a new CV was supplied or creating a revised CV was requested.
3. New photos go in `assets/` with descriptive, space-free filenames and alt text.
   Use CSS for display crops. Keep unknown locations and dates unstated.
4. A publication update may affect the bibliography, homepage selected work,
   project descriptions, and manuscript status. Deduplicate by DOI.
5. Run `quarto render`, then `python3 scripts/check_site.py`. If a browser preview
   is available, check desktop and mobile navigation, text, photo crops, and links.
6. Inspect the diff and commit related changes together with a clear message.
7. Follow the current user's publication instruction. A request to publish an update
   authorizes pushing it after checks. If they requested a draft, keep it on a branch
   or preview. Do not infer standing automatic-publication consent from these instructions.
8. Pages must use **GitHub Actions** as its publishing source. A branch-based
   Jekyll publisher can overwrite the Quarto site with the repository README.
   After a push to `main`, verify the build, deployment, and actual public-site
   checks before saying the public website has been updated. A deployment success
   alone does not establish that the correct website is being served.

## Commands

```sh
quarto render
python3 scripts/check_site.py
quarto preview
```

Quarto 1.7.34 is pinned in `.github/workflows/publish.yml`. There are no R or Python
scientific-package dependencies for this website. Never commit credentials or tokens.
